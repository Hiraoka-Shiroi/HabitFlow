# HabitFlow Studio 2.2.0

Личный веб-трекер привычек, планировщик дел и учёт финансов. React + TypeScript + Vite + Supabase.

## Возможности

- **Стартовый экран авторизации:** при открытии показывается вход или регистрация. Само приложение доступно только после входа.
- **Привычки:** круговые отметки, серии и история выполнения.
- **Годовая активность:** плотная сетка дней в стиле contribution graph — 53 недели × 7 дней.
- **Дела:** универсальный планировщик с категориями, поиском, приоритетами, датой и временем дедлайна, статусами и редактированием.
- **Финансы:** доходы и расходы в тенге, категории, заметки, общий баланс и месячная статистика.
- **Календарь:** привычки и задачи.
- **Аналитика:** выполнение привычек, серии, задачи и финансовый результат.
- **Темы:** цветная светлая и приглушённая тёмная тема.
- **Локальное хранение и экспорт:** записи сохраняются в браузере; данные можно выгрузить в JSON. Для нескольких устройств нужен Supabase.

## Требования

- Node.js 18+
- npm

## 1. Установка и запуск

```bash
npm install
cp .env.example .env
```

## 2. Подключение Supabase

1. Создай проект в Supabase.
2. В **Project Settings → API** скопируй Project URL и публичный anon/publishable key.
3. Заполни `.env`:

```env
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_SUPABASE_ANON_KEY
VITE_ALLOW_SIGNUP=true
```

4. В Supabase открой **SQL Editor**, выполни целиком `supabase.sql`.
5. В **Authentication → URL Configuration** добавь локальный адрес разработки и домен опубликованного сайта в Redirect URLs.
6. Запусти приложение:

```bash
npm run dev
```

После настройки появится стартовый экран с формами входа и регистрации. Пока Supabase не подключён, вместо формы отображается экран с шагами настройки — это не даёт случайно пользоваться локальным приложением вместо личного облачного аккаунта. При первом запуске создай свой аккаунт. Если в Supabase включено подтверждение email, подтверди адрес из письма и затем войди.

## 3. Закрыть регистрацию для остальных

Если HabitFlow нужен только тебе:

1. Сначала создай свой аккаунт и убедись, что можешь войти.
2. В настройках Supabase Auth отключи разрешение на регистрацию новых пользователей (**Allow new users to sign up / Enable sign-ups** — название может отличаться в интерфейсе).
3. Не удаляй уже созданный аккаунт. Обычный вход для существующего пользователя останется доступен.
4. Чтобы убрать вкладку «Регистрация» с экрана входа, измени локальный `.env` и переменные окружения хостинга на `VITE_ALLOW_SIGNUP=false`, затем перезапусти/пересобери сайт.

Отключение регистрации в Supabase — настоящая защита; `VITE_ALLOW_SIGNUP=false` только скрывает кнопку в интерфейсе. Не отключай регистрацию до создания первого аккаунта: иначе не получится зарегистрироваться.

## 4. Синхронизация между устройствами

Опубликуй приложение на Vercel, Netlify или другом статическом хостинге и добавь туда те же переменные `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`. Открывай один и тот же HTTPS-адрес на ПК, ноутбуке и телефоне и входи под одним аккаунтом. Все устройства читают записи из одной базы Supabase. Сейчас данные загружаются при входе/открытии приложения; для автоматического обновления уже открытой вкладки в реальном времени требуется отдельная настройка Supabase Realtime.

## Безопасность

В `supabase.sql` включён Row Level Security для всех пользовательских таблиц. Политики разрешают операции только с записями, где `auth.uid() = user_id`. Во фронтенде используется только публичный anon/publishable key. Никогда не помещай `service_role` key в `.env` клиентского приложения.

## Сборка и публикация

```bash
npm run build
npm run preview
```

Для публикации укажи `npm run build` как build command и `dist` как output directory.
